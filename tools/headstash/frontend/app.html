How this works


  1. Loading. A small loader you saved, whose hash is published in the governance proposal, asks the Headstash contract for its frontend contract. It downloads this page's gzip chunks from the chain and checks every chunk and every file against the sha256 values in the governance-published manifest. Nothing here comes from a web server.
    2. 

  2. Notes. Your allocation is split into fixed-denomination notes. From your key, the page derives one secret per note: HKDF-SHA256(key, "terp-hs-note-secret-v1", campaign‖identity‖index). From each secret it derives a key commitment and a nullifier. Your key signs a single registration message (EIP-191) and is then wiped. The notes file stores only the per-note secrets, never your key, and it records each note's status on this device.
    3. 

  3. Register. Registration publishes your key commitments, signed by your eligible address, in transactions of up to 32 notes. Each one is sent from a throwaway wallet whose fee is covered by a fee grant from the relay.
    4. 

  4. Claim. Once an anchor that includes your notes has been accepted, each note gets a zero-knowledge proof. The proof shows the note is in the registered set without revealing which one. Each claim is sent from a separate fee-granted wallet derived from that note's secret, so the claims cannot be linked to each other or to your eligible address. The chain rejects a reused nullifier. This page never queries the nullifier set; it tracks status in your file.
    5. 

  5. Penumbra (preview). This section checks a Penumbra address and shows the IBC transfer parameters. It does not send anything yet.
