## Serving the page
- One nginx on the RPC node host serves the claim page behind your existing DNS tunnel. It serves the loader `tools/headstash/frontend/loader.html` (not in the manifest, not on chain), with its placeholders `__REST__ __RELAY__ __CHAIN__ __HEADSTASH__ __DENOM__ __GP__ __CG__ __RG__ __MANIFEST_SHA__` filled. The loader resolves the page from chain: a smart query `/cosmwasm/wasm/v1/contract/terp1ed7t…p60r86/smart/{frontend_contract:{}}`, then the manifest and each chunk from terp1llutyfy…0e5n9, then sha256 check, gunzip, file-hash check.
- `__REST__` is the node's LCD on 127.0.0.1, exposed only through nginx with a GET-only allowlist on `/cosmwasm/wasm/v1/contract/<those two addresses>/smart/`. The relay (127.0.0.1:18795 per docs/mainnet-deploy-runbook.md; claims POST per docs/circuit/FE-CLAIM-SPEC.md) sits behind the same nginx, with an origin allowlist instead of the dev CORS `*` (docs/circuit/DEPLOY-REVIEW.md:53).
- This can only be configured after A14 passes and A19 has sealed the chunks (the addresses and `current` must exist).
- There is no nginx config or snippet in the repo.
