# Wallet gaps

A restart must not create a new key for a job that already has one. Two different secrets were being treated as if a fresh process could invent them.

## Operator key

`POST /v1/sign` is the QC identity for entitle and settle. Until 2026-10-28, `load_keys` generated a new ed25519 key whenever `SVG_MINT_FED_SK_HEX` was unset, logged the public key, and dropped the secret on exit.

The fed now uses one file, `~/.terp/svg-mint-fed.sk` (override `SVG_MINT_FED_SK_FILE`):

- Missing file: generate once, write 32 raw bytes at mode `0600`, log the public key.
- Existing 32-byte file: load it. The public key after a restart matches the previous start.
- Wrong length: exit. The file is not replaced.
- `SVG_MINT_FED_SK_HEX` set and the file present with different bytes: exit. No silent rotation.

The hex env is not required. Leaving it unset is how the secret stays out of `systemctl show`.

The mint cell default is `~/.terp/svg-mint-fed-cell.json`, not `/tmp/svg-mint-fed-cell.json`.

## ZEC spend key

`svg-mint-zrt` does not generate a seed on `notes`, `balance`, `sync`, or `send`. Only `init` creates `spend.seed`. A second `init` fails. `sync` does not write the ledger. `send` accepts only the donation UA, then exits because the prover is not linked.

Do not `init` `~/.terp/svg-mint-zrt` on the house to "get a wallet back." That directory was absent on 2026-10-28. So were `age-identity.txt`, `data.sqlite`, and any UFVK file. `~/.terp/dregg-hd.seed` is present and cannot spend ZEC. Notes paid to the old diversified addresses stay on chain and are invisible to a new seed.

Search backups for `age-identity.txt` and `data.sqlite` before any `init`. Do not print what you find.
