# FE handoff — DREGG prices (do not hardcode)

**This deploy:** show **`zec`** and **`native` only**. Do not label or Pay ETH / Base / BTC. Packet: `FE-ZEC-NATIVE-ONLY.md`.

DREGG is the source of truth for rail amounts. Do **not** bake ETH / Base / BTC / ZEC / native numbers into the page. On load (and whenever you render Pay), call **`GET https://dregg-svg.permissionless.money/v1/prices`** (CORS is on). This endpoint is **amounts only**: use `eth.ether` / `eth.wei`, `base.ether` / `base.wei` / `base.chain_id` (8453), `btc.btc` / `btc.sats`, `zec.zec` / `zec.zat`, `native.display` / `native.amount` / `native.denom`, and `bogo_cap`. `ok: true` is **not** a Pay signal (the body may also include `checkout_ready` from `checkout_now`). Product defaults are **0.0005 ETH** (same wei on Base), **0.000015 BTC**, **0.0015 ZEC**, **100** TERP|THIOL. **Pay only if `checkout_ready === true` and `GET /v1/pay-targets` is HTTP 200.** `/health` is always HTTP 200 (liveness); disable Pay when `ok`/`checkout_ready`/`pay` is not true. A prices fetch failure is not a substitute for those gates; still do not show Pay without a 200 pay-targets. Hide ZEC until checkout `zec_uri` is non-null; hide Base if `base_addr` is missing from pay-targets.

Checkout still needs **`GET {DREGG}/v1/pay-targets?recipient={terp1}`** once per checkout for addresses and `memo_hex` (never cache across checkouts; never put `terp1` on ETH/Base/BTC/ZEC). The amount fields on that payload (`eth_wei`, `base_wei`, `btc_sats`, `zec_zat`, `native_amount`) **must match** `/v1/prices`; if they disagree, treat it as a server bug and do not broadcast. Use `eth_wei` / `base_wei` as the tx `value`, `btc_sats` for the BTC output, and the ZIP-321 URI as-is for ZEC. Labels on the four rail buttons come from `/v1/prices` only. Full contract: `crates/dregg/svg-mint/FE-HANDOFF.md`.
