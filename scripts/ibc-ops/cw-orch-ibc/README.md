The DAO scripting that lived here is part of `dao-foundation-suite`.

Bins: `cargo run -p dao-foundation-suite --bin foundation_delegate` writes only the FIAB-SUBDAO proposal. The instantiate attaches `1000000000000uterp` and `1000000000000uthiol`. `--broadcast` discovers proposal module A and signs that JSON with `DAO_MEMBER1_MNEMONIC` through cw-orch. It does not call `terpd`. `--bounty --member <terp1> --bounty-code-id <id> --bounty-init <json>` writes the BOUNTY-SUBDAO proposal instead: single-choice plus that bounties module, seeded with `1000000000000uterp`. That path does not broadcast. `steward_daos` writes the liquidity-steward proposals and does not broadcast. Also `quorum_redelegate`, `quorum_broadcast`.

`quorum_redelegate --rebalance` writes every legal redelegation into `02-next-block-unsigned.json`, including the terpz 22% outflow once that source lock has ended. Moves that are still locked stay in `03-terpz-share-design.json` and are left out of the transaction. The dry run is the default and sends nothing. `--broadcast` signs that unsigned tx with `TERPZ_FOUNDATION_MNEMONIC` through cw-orch and submits it to `http://192.168.10.101:9090`. It does not import the operator key, does not call `terpd`, and does not create a validator. `quorum_broadcast --foundation-only` signs the same file and skips create-validator; pass `--node tcp://192.168.10.101:26657` on that command. `gov_deposit` writes an unsigned deposit plan and does not broadcast.

`gov_fund` is the reusable cw-orch broadcaster. Repeat `--deposit <id>:<amount><denom>` for any gov proposal. With no `--deposit`, it sends 5,000 TERP to proposal 60 and 5,000 TERP to proposal 61 in one transaction from `MAIN_MNEMONIC`. A wallet-only run does not read the DAO member phrases. `--dao-fund` is the only path that uses `DAO_MEMBER1_MNEMONIC` and `DAO_MEMBER2_MNEMONIC`: it opens a treasury deposit, both member keys vote yes, and the same run executes once those two votes pass. `--env-file scripts/ibc-ops/cw-orch-ibc/.env` resolves from the current directory, from `crates/terp-rs`, or from the workspace root. Add `--broadcast` only after `MAIN_MNEMONIC` is the real hot-wallet phrase. The dry run prints the depositor address and sends nothing.

`dao_upgrade` reads `networks/upgrades/v6.3/draft_proposal.json` and refuses to run unless that file, `proposal.json`, `metadata.json`, and both plans' `cosmovisor.json` and `binaries.json` files describe the same v6.3.0 and v6.4.0 cut. One run proposes that expedited software upgrade from the foundation DAO, both member keys vote yes, and the run executes it. A second DAO proposal in the same run votes yes on cosmos gov proposals 60, 61, and 62. 62 is the upgrade this run submits. v6.4 is armed by the v6.3 binary and is not its own governance message. The DAO pays the draft's 100,000 TERP expedited deposit. Add `--broadcast` only after 60 and 61 are in the voting period and 62 does not exist yet.

The ignored terpd instantiate2 test is `dao-foundation-suite`'s `dao_init2_chain`.
